Unit E1 EmissionCost (phase 14.4, D-P27): the per-event cost of the run log, the state store and the substrate tee. Python first, bytes unchanged.
Host: shared, load 17 to 160 during the measurements (see each section); every figure is CPU time (thread or process), min of several runs; a before and an after run alternate.
Harnesses (kept in /root/.cache/gsd-redact-work/Wr144EmissionCost, not in the repository): prof.py (the `profile`-module per-thread profile of tests/perf/scheduler_engines.py section 5, same method),
lightprof.py (two thread-CPU clock reads around each function, no profiler), bench.py (per-call CPU), strace for syscall counts. BEFORE = git HEAD tree (git archive), AFTER = HEAD + this unit's diff only.

== 1. What the profile hid
The `profile` module adds about 10 us per Python call, so call-heavy code (pathlib, json, redact) is inflated. Same dry run, same 13 tasks, without the profiler (lightprof, BEFORE tree, min of 4 runs):
process CPU 3.20 s of which interpreter startup and imports about 0.4 to 0.5 s; runlog.emit 502 calls 583 ms (1.16 ms avg), observability.emit_gsd_omp 195 calls 323 ms, stream_subagent_status 68 calls 201 ms,
SwarmStateStore.append_gsd_audit 323 calls 115 ms, redaction inside emit 139 ms. So emission is about 20% of the process CPU, not 36%; the profile still ranks it first.

== 2. Callee level (what one call costs)
- emit_gsd_omp = 42 syscalls per call (strace): 3 swarm_dir resolutions (getcwd + 4 lstat + stat + stat .gitignore each, via Path.cwd().resolve()), a SwarmStateStore constructor (mkdir EEXIST + is_dir stat + 2 exists), two text-mode appends
  (openat, fstat, lseek x3, ioctl TCGETS, write, close = 8 each), uuid4 getrandom. Syscalls are 5 to 10 us each here and much more under load: they, not Python, were the cost.
- stream_subagent_status = two emits (per-unit + the stream record) + audit + store constructor, so about 2x that.
- SwarmStateStore.update: json.dumps(indent=2) twice (the pure-Python encoder), two write_text_atomic (not in this unit's file list; unchanged).
- With SUBSTRATE_URL set (as in this shell) every tee'd event runs substrate_tee.tee -> workspace.credential -> manifest.get_agent TWICE: each a json.loads of the whole agent record (about 1.5 ms) plus a roster stat+resolve.
  Measured emit tee=False 0.11 ms vs tee=True 3.0 ms per call (profile before the fix, no token: the row stays local and says so once).
- redact.redact is about 12% of the profiled thread (4 ms per event under the profiler, 30 to 45 us unprofiled for a small payload). Its _name_tokens is uncached; redact.py is not in the unit's file list: not touched.
- "Skip the stream when no OMP session listens": nothing in the code listens. emit_gsd_omp / stream_subagent_status write run-log events (events.jsonl, the substrate tee maps them to `note`), and tests read them
  (tests/test_scheduler_continuous.py:725, tests/typecheck/test_group_g4b_defects.py:32, tests/test_substrate_tee.py:910). There is no session, flag or subscriber test, so a skip rule would change events.jsonl: NOT done.
- log_phase (one event per pass): left as is (it changes events.jsonl; no test pins the count but every pass of a dry run dispatches, so "only on change" would save nothing here). Option for the user.

== 3. Changes (bytes written are identical)
swarm/paths.py: swarm_dir remembers one resolution per input (SWARM_DIR, root, cwd only where one of them is relative or absent); create=True still stats .gitignore on every call; append_text = one write(2) on an O_APPEND fd
  (the bytes of open(path,"a",encoding="utf-8").write(text), nothing buffered across calls).
swarm/runlog.py: emit appends through append_text.  swarm/state_store.py: audit log through append_text; constructor skips mkdir when the state file exists; update renders its JSON once for both files (unserialisable extra: nothing written, as before).
swarm/manifest.py: agent_slug (immutable str, cached roster not aliased; same cache key rules, 2 s rule untouched).  swarm/workspace.py: credential looks the slug up once through agent_slug.
docs/swarm-command-center.md: two lines (append contract, SWARM_DIR resolution). tests/test_emission_cost.py: 36 tests.

== 9. Did not improve / options for the user
- Process CPU of the dry run: no measurable change at this noise (section 5). The saving is real per event (section 6: emit 2x, tee 3.7x, emit_gsd_omp 1.8x, stream 2.6x, swarm_dir 11x) but emission was about 20% of the process.
- SwarmStateStore.update 594 -> 537 us and _drive_gsd_state 1486 -> 1089 us: dominated by two write_text_atomic (swarm/atomic_file.py: uuid4 + Path.write_text + replace); an os-level write there would help (file not in this unit's list).
- redact: lru_cache on redact._name_tokens (pure, 1100 calls per 100 events) would cut part of the remaining 12%; redact.py not in the list. The Rust scanner stays opt-in.
- log_phase once per pass only on change, and any skip of the gsd/omp streams, change events.jsonl: need your decision. Rust: nothing in this profile justifies it now (redaction is the one remaining emit cost and has the opt-in scanner).
- AGENTS.md line needed (I may not edit it): under the state-dir rule add "swarm_dir() remembers one resolution per (SWARM_DIR, root, cwd-if-relative) input; run-log and audit lines are appended with one write(2) (swarm.paths.append_text)".
- Known limit: a symlink re-pointed under an unchanged SWARM_DIR/root string is not seen by the swarm_dir cache (git toplevel was already cached by paths._resolve).
