## Findings that limit this record

1. **The `rust-sandbox` leg is not evidence at this HEAD.** All 777 sandbox calls were `fallback:E-DEP`; zero were served by the guest. The committed guest pin did not match the built guest (D-P25: `ffa7b28a...` committed, `91b0970e...` built), so every sandbox call declined and Python answered. Its 12/12 is Python's answer. A sandbox leg counts only when the guest is served. Superseded: the P2 re-pin `54fd751` moved the pin to the built digest, and `tests/parity/records/14.5/U37d-sandbox-write-harness.json` is the sandbox run at the new pin (696 Rust-served cells).
2. **`cargo test -p gsd-adapter -p gsd-sandbox -p gsd-sdk` exits 101 at `0b63a38` with 19 failing tests**, all in the D-P25 guest-pin cascade: 17 `sandbox_engine::*` unit and integration tests (`guest module bytes do not match the manifest SHA-256 digest`), `gsd_engine_backend::a_read_prints_no_failover_notice_under_any_backend_setting` (the sandbox answers `E-DEP` and the host answers, from the same mismatch), and `guest_digest::built_guest_digest_matches_the_committed_pin`. After the P2 re-pin the same packages were run at `d0617a5` (U3.8b agent: `cargo test -p gsd-adapter -p gsd-sandbox -p gsd-sdk --locked --offline`, exit 0, 424 passed). The orchestrator did not re-run them at `2535652`.
3. The R7 agent's interim records (`interim-64f5759/`) were taken on `53df964`, before D-P25 and before the flip build. They are not evidence for HEAD and are kept only as history.
